# 后台布局方案

> 说明：本方案用于约定 GA Sprite Birds GUI 的后台页面基础布局结构。本项目无需登录页。

---

## 1. 路由与适用范围

### 1.1 路由模式

本项目使用 **History 模式**（`createWebHistory`），URL 形如 `/policy/dashboard`，不带 `#`。

> **部署注意**：History 模式要求服务器将所有路由请求 fallback 到 `index.html`，否则刷新会 404。
>
> Nginx 参考配置：
> ```nginx
> location / {
>     try_files $uri $uri/ /index.html;
> }
> ```
>
> Vite dev server 已内置此 fallback，本地开发无需额外配置。

### 1.2 路由与布局映射

1. `/policy/**` 路由
   - 统一使用「后台主布局」（Policy Layout）；
   - 主布局内部实现：顶部通栏 + 左侧菜单 + 右侧内容 + 底部通栏。

---

## 2. 整体结构概览

页面整体拆分为三大块：

1. 顶部通栏 Header（通栏，含 Logo+操作区）
2. 中间区域：左侧菜单 + 右侧内容（含预留二级导航区）
3. 底部通栏 Footer（仅后台布局显示）

整体风格：框架层全宽铺满，但主内容区遵循“**背景全宽，内部内容控宽**”原则，类似成熟后台模板的通栏骨架 + 内容层设计。

---

## 3. 顶部通栏 Header

### 3.1 位置与宽度

- 位置：页面最上方通栏，宽度 100%。
- 内部使用左右布局（flex）：左侧固定 200px，右侧自适应。

### 3.2 左侧 Logo 区（固定 200px）

- 宽度固定 200px；
- 内容水平、垂直居中；
- 显示内容： 
  - 使用 `VITE_APP_TITLE` 作为系统名称（例如：GA RAG System）；
  - 未来如有图标/logo，可在此区域追加图标 + 文本。

### 3.3 右侧操作区（自适应，右对齐）

- 占据除左侧 200px 以外的所有宽度；
- 使用 flex 布局，整体 **右对齐**；
- 包含元素：
  1. 明暗模式切换按钮；
  2. 主题设置入口；
  3. 语言切换；
  4. FastAPI 状态标识。

### 3.4 Header 内按钮颜色继承注意事项

Header 区域所有按钮（含语言切换、主题设置等）的文字颜色，**必须通过 `:style="{ color: headerTextColor }"` 显式注入**，而不是依赖 CSS `color: inherit`。

原因：`el-dropdown` 的 trigger slot 内部会创建额外的 DOM 包裹层，导致 `color: inherit` 链在该层断裂，子按钮无法正确继承 Header 的文字颜色。标准 `el-button` 同样受此影响。

正确做法示例：

```vue
<el-button :style="{ color: headerTextColor }" text>
  语言切换
</el-button>
```

`headerTextColor` 来自 `var(--theme-header-text)`，由主题系统统一提供。

## 4. 中间区域：左侧菜单 + 右侧内容

### 4.1 左侧菜单栏（固定 200px）

- 宽度固定 200px；
- 建议使用 Element Plus 的 `el-aside` + `el-menu` 实现；
- 当前阶段： 
  - 菜单按当前 FastAPI 能力收敛为「音频生成」和「主题设置」；
  - 不添加 API 未支持的后台功能入口。

### 4.2 右侧内容区（自适应宽度）

右侧内容区继续拆分为两层：

1. 顶部二级导航 / TAB 通栏（预留）
   - 位置：紧贴 Header 下方、主内容上方；
   - 用途：未来放二级导航、Tab、面包屑等；
   - 当前： 
     - 可根据路由 meta 决定是否渲染；
     - 没有内容时可以不显示，不影响整体布局。
2. 主内容展示区
   - 用于承载当前路由对应页面（`<router-view />`）；
   - 宽度自适应剩余空间，高度随内容扩展；
   - 外层保持整宽，但内部内容不直接无限拉伸；
   - 统一采用“**框架背景全宽，页面按场景选择内容宽度**”的方式做视觉控制。

### 4.3 Main 内容区统一适配规范（新增）

后续后台所有进入 `main` 的页面，统一按以下规则开发：

1. **外层框架全宽**
   - `el-main` 区域保持自适应铺满；
   - 页面背景、留白、滚动行为继续由主布局统一承接。

2. **列表 / 查询 / 表格页默认全宽**
   - 列表、查询、表格、数据看板等以信息密度为核心的页面，默认使用全宽；
   - 避免在笔记本屏幕下浪费横向空间；
   - 超宽表格内部使用横向滚动或列宽控制，不建议把整个页面收成窄卡片。

3. **表单 / 详情 / 局部操作页控宽**
   - 页面中的白色卡片、模块背景、步骤条容器等，默认保持全宽；
   - 真正的标题、表单、步骤条、详情正文，需要在白色背景内部再包一层内容容器；
   - 内容容器的最大宽度，以“**笔记本用户全屏查看时刚好舒适铺满**”为基准；
   - 目标不是极窄居中，也不是 2K / 4K 屏幕下无限拉长。

4. **当前页面宽度类**
   - `page-container`：基础页面容器，默认占满可用宽度；
   - `page-container--fluid`：列表 / 查询 / 表格页使用，不限制最大宽度；
   - `page-container--comfortable`：常规表单、详情、主题设置页使用，最大宽度约 1200px；
   - `page-container--narrow`：简单表单、登录后局部配置页使用，最大宽度约 960px；
   - `page-container--wide`：复杂配置、大型看板使用，最大宽度约 1440px。

5. **设计原则**
   - 背景负责承接页面结构与层次；
   - 内容层负责控制阅读宽度与交互密度；
   - 这样在大屏下不会显得过于松散，在笔记本下又能保持足够利用率。

6. **适用范围**
   - 表单型页面：如新增、编辑、详情、参数配置等页面；
   - 组合配置页：如左右分栏设置、分步配置、复合内容编排类页面；
   - 列表页优先使用 `page-container--fluid`，让查询区、工具栏、表格获得完整横向空间；
   - 如遇超宽表格，可在此原则下使用更宽的内部内容层，但仍不建议无控制地无限拉伸。

7. **当前已确认的实现口径**
   - `main` 区采用统一策略：**框架背景全宽，页面按场景控宽**；
   - 这条规则可作为后台项目的通用主内容区规范，后续其它模块或其它项目直接沿用；
   - 若无特殊业务说明，不再单独设计“整张白卡整体收窄”的页面方案。

---

## 5. 底部通栏 Footer

### 5.1 展示范围

- 在后台主布局中显示。

### 5.2 内容与格式

- 文案右对齐显示，两行：

1. 第一行：
   - `{系统名称}管理系统 VITE_APP_BUILD_VERSION`
   - `{系统名称}` 使用 `VITE_APP_TITLE`；
   - `build-2025.05.20` 当前可写死为版本号，后续可改为环境变量（例如：`VITE_APP_BUILD_VERSION`）。
2. 第二行：
   - `©2025 {系统名称} Corporation All Rights Reserved.`
   - 同样 `{系统名称}` 使用 `VITE_APP_TITLE`。

---

## 6. 技术实现建议（简要）

1. 布局骨架使用 Element Plus 官方推荐的 `el-container` 系列组件：
   - `el-header` / `el-aside` / `el-main` / `el-footer`；
   - 中间再配合 flex 控制左右布局与对齐。
2. `main` 内容区建议采用双层结构：
   - 第一层：全宽的页面块 / 卡片块 / 白色背景块；
   - 第二层：限制最大宽度的内容容器；
   - 用于承载步骤条、表单、筛选项、正文等真实内容。
3. 明暗模式、多语言
   - Header 已接入主题切换（Pinia + CSS 变量）；
   - 文案应统一放入 i18n 语言包。
